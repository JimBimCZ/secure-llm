# Decisions

One line per non-trivial decision, newest section last.
Format: `YYYY-MM-DD — decision — why — what was rejected`

## Seed data

2026-08-26 — Seed corpus is 10 self-authored synthetic PC-hardware notes — keeps the repo free of third-party copyrighted prose and lets the "synthetic data only" claim in the README be literally true — rejected scraping and rewriting vendor/wiki pages, which is faster to bulk-fill but weakens both points.

2026-08-26 — Seed documents are written in one persona's voice (alice's own build notes), not as encyclopedia entries — gives the synthetic personal data a natural reason to exist, makes ownership coherent when the loader attaches every document to one `sub`, and makes retrieved answers read like notes rather than reference text — rejected neutral spec-sheet prose, which would leave the anonymizer nothing to catch.

2026-08-26 — Synthetic names, e-mails and phone numbers are woven through the corpus (6 people, `example.com` per RFC 2606, patterned `+420 6xx xxx xxx` numbers) — the anonymization round-trip is a mandatory demo and needs real material in the seed rather than PII typed in live on camera; also exercises both the regex path and the capitalised-bigram name heuristic — rejected keeping the corpus purely technical.

2026-08-26 — Seed spans three formats (7 `.md`, 2 `.txt`, 1 `.pdf`) — proves all three accepted ingest formats on first boot instead of leaving the PDF path untested until a manual upload — rejected all-Markdown.

2026-08-26 — The PDF is generated by a committed script (`seed/sources/make-pdf.sh`, macOS `cupsfilter`) from a Markdown source, not hand-placed as an opaque binary — a committed binary should be reproducible from something diffable — rejected adding a PDF library as a dependency for what is authoring-time seed data.

2026-08-26 — The PDF's source Markdown lives in `seed/sources/`, outside the ingest glob — a loader globbing `seed/*` would otherwise ingest the networking content twice and put two near-identical chunk sets into retrieval — rejected keeping the source beside the PDF.

2026-08-26 — Text folded to ASCII before PDF conversion — `cupsfilter`'s text path writes MacRoman, so em-dashes and bullets extract as mojibake and would poison the chunks — rejected leaving the typography intact in the PDF.

2026-08-26 — The corpus deliberately omits laptops and soldered/LPDDR memory — gives a reliable, repeatable question for the "Not found in your knowledge base." path from CLAUDE.md §6, so that demo beat does not depend on improvising a miss on camera — rejected covering every component category evenly.

2026-08-26 — Two seed documents deliberately disagree (`04-motherboard-chipset.md` and `05-storage-nvme.md`, on whether the second M.2 slot steals graphics lanes) and the storage note names its own untested assumption — makes multi-citation answers demoable rather than hypothetical, and gives a question where the honest answer is "the sources conflict" — rejected a fully consistent corpus.

## Architecture

2026-08-26 — `LlmProvider` split into `LlmProvider.answer()` and `EmbeddingProvider.embed()`, each with its own env var — Anthropic has no embeddings endpoint (their docs say so and point at Voyage AI), so a combined interface cannot be implemented by the `anthropic` provider at all; two external concerns get two seams — rejected keeping one interface with the Anthropic provider secretly calling a second vendor, which hides the fact that there are two services and two keys.

2026-08-26 — Embeddings run locally in-process via `@huggingface/transformers` + `Xenova/all-MiniLM-L6-v2` (384 dims) — no text leaves the process to be embedded, so only the anonymised answer call crosses a network boundary, which lowers the data-protection profile argued in the classification; also removes a second API key from the setup — rejected Voyage AI (adds a key and a vendor) and rejected OpenAI embeddings (adds a vendor and a key for no gain here).

2026-08-26 — The embedding model is baked into the Docker image at build time (`env.localModelPath`, `env.allowRemoteModels = false`) — a runtime download from the Hugging Face Hub would break the zero-manual-steps requirement on a slow or offline network, and would make first run depend on a third party's uptime — rejected downloading on first boot.

2026-08-26 — `chunks` stores the `embedding_model` that produced each vector, and retrieval filters on it — vectors from different models are not comparable, so switching `EMBEDDING_PROVIDER` against an existing database would silently return nonsense rankings instead of an error — rejected assuming the embedder never changes.

2026-08-26 — The `mock` embedder hashes tokens into a normalised 384-dim vector rather than returning random or constant vectors — anyone running `docker compose up` with no API key must get working retrieval; random vectors would score under `RAG_MIN_SCORE`, the citation guard would reject every answer, and the app would look broken while behaving correctly — rejected a pure hash of the whole chunk.

2026-08-26 — Auth.js v5 accepted at `5.0.0-beta.32` despite being beta — v5 is the version whose generic OIDC provider is configured purely from env, which is what makes the Entra ID swap configuration-only; v4's provider model would need code changes to swap IdP — rejected v4 (defeats a hard requirement) and rejected hand-rolling OIDC (more code to defend, no upside).

## Slice 1 — skeleton, compose, health, logging

2026-08-26 — Startup work (migrations, and later the retention purge) runs in Next's `instrumentation.ts` `register()` hook — Next guarantees `register()` completes before the server accepts requests, so a migration cannot race the first request, and it keeps startup in one obvious documented place rather than an entrypoint shell script a reader has to find — rejected a `docker-entrypoint.sh` running a compiled migrate script, which needs a second build artefact and splits startup across two files.

2026-08-26 — Node-only startup code lives in `instrumentation.node.ts`, reached by dynamic import — `instrumentation.ts` is compiled for the edge runtime too, and a runtime `if` does not stop static analysis; the build warned about `process.version` until the Node code moved behind a dynamic import — rejected keeping one file with a guard clause.

2026-08-26 — Runtime image is `node:22-bookworm-slim`, not Alpine — the local embedding provider in slice 3 pulls in onnxruntime-node, which ships glibc binaries and does not run on musl; choosing Alpine now would mean rebuilding the image layer in slice 3 — rejected `node:22-alpine` despite the smaller image.

2026-08-26 — TypeScript pinned to 5.9.3 rather than the published 7.0.2 — TS 7 is the native rewrite and Next 16's toolchain targets 5.x; an eight-hour build is the wrong place to debug a compiler-generation mismatch — rejected latest-is-best.

2026-08-26 — The builder stage sets a placeholder `DATABASE_URL` — `next build` imports every route module to read its config exports, which reaches the zod env validation and fails the build without one; the value is never connected to — rejected making env validation lazy, which would trade a two-line Dockerfile comment for cleverness in the code path that most needs to be obvious.

2026-08-26 — `/api/health` returns a generic "database unreachable" to the caller while the detailed error goes to the log — driver errors can carry the connection string, and health endpoints are typically the least authenticated surface in the app — rejected returning the driver message.

2026-08-26 — Personal working notes are git-ignored by name — the repo is public, so publishing a private working document should be a deliberate act, not a side effect of `git add -A` — rejected relying on remembering to leave them out of each commit.

## Slice 2 — OIDC sign-in, roles and the guard

2026-08-26 — The Keycloak-in-Docker issuer mismatch is solved with `KC_HOSTNAME=http://localhost:8080` plus `KC_HOSTNAME_BACKCHANNEL_DYNAMIC=true` — Keycloak then reports one issuer (`localhost:8080`, what the browser uses and what lands in `iss`) while advertising backchannel endpoints on the container network, so token exchange and JWKS work from inside the app with no issuer mismatch and no code — rejected `extra_hosts: localhost:host-gateway`, tested and shown not to work because the built-in `127.0.0.1 localhost` entry wins resolution; rejected proxying Keycloak under the app origin, which works but adds a route the production topology would not have.

2026-08-26 — The server reaches the IdP through `idpFetch`, wired in as Auth.js's `customFetch` — Auth.js discovers from the issuer URL and ignores `wellKnown` (verified in `@auth/core/lib/actions/signin/authorization-url.js`, which builds `new URL(provider.issuer)`), and that URL is by definition the browser's address, unreachable from a container; `customFetch` is the supported hook and rewrites only the issuer's origin, so it is a plain fetch against a public IdP — rejected `wellKnown`, which is silently ignored on this path.

2026-08-26 — The OIDC provider declares `profile: (p) => ({ id: p.sub, ... })` — without it Auth.js generates its own user id and puts that in `token.sub`, producing a **different subject on every sign-in**; since everything a user owns is keyed by subject, that would have silently detached each user from their own documents in slice 3 and looked like a retrieval bug — found by asserting the session subject equals the IdP subject rather than by reading code.

2026-08-26 — The provider id is `oidc`, not the vendor name — the id appears in the callback URL (`/api/auth/callback/oidc`), so naming it after the provider would hard-code the vendor into a URL registered at the IdP, breaking the configuration-only swap required by §3 — rejected `keycloak` as the id.

2026-08-26 — Env validation is skipped during `next build` (`NEXT_PHASE === "phase-production-build"`) instead of supplying build-time values in the Dockerfile — `next build` imports every route module to read its config exports, which reaches the env schema; satisfying it in the Dockerfile would mean baking six placeholder values, including one named `OIDC_CLIENT_SECRET`, into an image layer of a repo that makes a point of secret hygiene — rejected the Dockerfile placeholders used in slice 1, now removed.

2026-08-26 — Authorization lives in one `requireRole()` guard that throws, with a matching `authErrorResponse()` — route handlers stay three lines and cannot accidentally fall through to a 200 when the guard rejects; a denied attempt is logged at warn as a security event — rejected returning booleans from the guard, which makes forgetting to check a silent failure.

2026-08-26 — Sign-in logs the subject and roles, never the display name or e-mail — the log is an audit trail of events, not a copy of the user directory, and §3 forbids personal data in logs — rejected logging the profile.

2026-08-26 — Roles are read from the token claim on every request, never from `users.role_snapshot` — the snapshot exists for display and for the admin count; if authorization read the database, revoking a role at the IdP would not take effect until the app happened to write a row — rejected treating the projection as authoritative.

## Slice 3 — ingest, chunking, embeddings

2026-08-26 — Chunk size is derived from the embedding model's 512-token input window, not chosen for taste — `all-MiniLM-L6-v2` silently truncates beyond 512 tokens, and measurement showed 32 of 40 chunks at the original ~800-token target overran it, so roughly a third of every document was stored and citable but invisible to retrieval; after resizing, 0 of 53 chunks truncate and top similarity rose from 0.44 to 0.51 — CLAUDE.md §6 was corrected to match; rejected keeping the ~800-token figure, which presumed a model that could read it.

2026-08-26 — Tokens are approximated at 3 characters each when budgeting a chunk — prose runs nearer 4.8, but tables and code are far denser; guessing low costs a slightly smaller chunk while guessing high costs silent truncation, so the error is deliberately one-sided — rejected shipping a tokenizer just to decide where to cut.

2026-08-26 — The `q8` (8-bit) model weights are used rather than float32 — 23 MB in the image instead of 96 MB, identical 384 dimensions, and measured separation held (related pair 0.339 vs unrelated −0.015) — rejected float32 for a four-fold image cost with no measured retrieval benefit.

2026-08-26 — `chunks.owner_sub` is denormalised from the parent document — retrieval then filters ownership in the same WHERE clause as the vector search, so a query cannot return another user's chunk even by mistake; §6 requires the filter to be in SQL, and this keeps it one predicate rather than a join — rejected joining through `documents` on every search.

2026-08-26 — Deleting a document is a single DELETE carrying the ownership predicate, returning 404 when it matches nothing — a request for someone else's document deletes nothing and does not reveal whether that id exists; verified by attempting a cross-user delete — rejected fetching, checking ownership in application code, then deleting.

2026-08-26 — The seed corpus is ingested on a user's first sign-in, not at startup — documents belong to a subject and no subject exists until someone signs in; it is idempotent (a user with documents is skipped) and cheap, ~2.7 s for 10 documents — rejected seeding at startup, which has no owner to attach to, and rejected precomputing embeddings into the repo, which would be wrong for whichever provider was not used.

2026-08-26 — `outputFileTracingIncludes` force-includes onnxruntime and sharp binaries — Next's module tracing follows imports and copied the JavaScript but not the `.so`/`.node` files beside it, so the built image failed at runtime with `libonnxruntime.so.1: cannot open shared object file` while `next dev` was fine; this class of bug only ever appears in the image — rejected copying node_modules wholesale into the runner.

2026-08-26 — Document byte size is read before text extraction — pdf.js takes ownership of the typed array it is handed and detaches the underlying buffer, after which `byteLength` reads 0; every PDF was recorded as 0 bytes until this was found — rejected reading the size after extraction.

2026-08-26 — The mock embedder drops stopwords and damps term counts, and does not use bigrams — all three were measured against the seed corpus: raw counts ranked a question the corpus *cannot* answer above ones it can (0.395 vs 0.107), which is exactly backwards and would defeat the citation guard; stopwords plus sublinear damping fixed the ordering (hole falls to 0.116) and took probes from 1/3 to 2/3 correct; adding bigrams made every probe worse, as 384 buckets are too few to hold them — rejected both raw counts and bigrams, on measurement rather than intuition.

2026-08-26 — The mock embedder is documented as a test and fallback path, not the demo path — `local` is the default, needs no API key, and is baked into the image, so anyone running `docker compose up` gets real semantic retrieval; the fallback exists because onnxruntime ships no darwin/x64 binary, so `npm run dev` outside Docker on an Intel Mac cannot load the real model — rejected claiming mock is "demoable", which measurement did not support.

## Slice 4 — ask endpoint, the LLM seam and the citation guard

2026-08-26 — Citations are 1-based POSITIONS in the chunk list sent to the model, never chunk ids — the model is never shown an id, so it cannot fabricate one that happens to exist; a citation either indexes the set we retrieved or it is out of range, and there is no third case for the guard to reason about — rejected asking the model to echo UUIDs, which is both error-prone and would let a hallucinated id collide with a real row.

2026-08-26 — The provider returns the model's citations verbatim, and `rag/answer.ts` decides which survive — a provider that quietly dropped out-of-range numbers would hide exactly the failure the guard exists to catch, and the audit trail would show a clean answer where a fabricated citation had occurred — rejected sanitising inside the provider.

2026-08-26 — The official `@anthropic-ai/sdk` rather than hand-rolled `fetch` — it owns retry policy on 429/5xx, typed errors and the exact request shape of a versioned API, and the §3 audit record needs the token counts it returns, which a hand-rolled client would have to guess; this is the one place the "30 lines of clear code" rule in CLAUDE.md §8 loses to a dependency, and the reason is in this line — rejected raw fetch, which would have made `gateway.ts` look more impressive while making the real call path worse.

2026-08-26 — `anthropic` and `gateway` share one `createMessagesProvider(name, client)` and differ only in how the client is constructed — that IS the argument the gateway file exists to make: swapping to a corporate AI Gateway is a base URL and an auth header (`Authorization: Bearer` instead of `x-api-key`, because a gateway authenticates the caller against itself, not against the vendor), and nothing about the prompt, request or parsing moves — rejected duplicating the call in both files, which would have implied the difference is larger than it is.

2026-08-26 — `LLM_PROVIDER` defaults to `mock`, and `mock` extracts rather than generates — §5 requires the app be fully demoable with no API key, so the default cannot be a provider that needs one; the mock scores every sentence in the retrieved chunks against the question and returns the best few verbatim with real citations, so retrieval, the guard and the source links are all exercised on the keyless path — rejected returning canned text, which would have demoed nothing.

2026-08-26 — Selecting `anthropic` without `ANTHROPIC_API_KEY` refuses to start, with no fallback to `mock` — an app that silently stops using the model you configured, and answers differently because of it, is worse than one that will not boot; verified by starting the image with the provider set and the key blank — rejected falling back, which hides a configuration error behind a working-looking app.

2026-08-26 — Blank environment variables are stripped before zod validation — an unset variable does not arrive as absent, it arrives as `""`, both from a `.env` shipping `ANTHROPIC_API_KEY=` and from Compose interpolating an unset name; zod treats `""` as present, so a blank optional failed `.min(1)` and a blank enum never reached its default, and `cp .env.example .env && docker compose up` would have failed on a fresh clone — rejected defaulting each variable a second time in `docker-compose.yaml`, which puts the same default in two files.

2026-08-26 — The similarity floor is applied inside the retrieval SQL, not after ranking — a question the corpus cannot answer then returns zero rows and no model call is made at all, rather than returning its six least-bad chunks and inviting an ungrounded answer; measured against the seed corpus, answerable questions score 0.363–0.586 and unanswerable ones (sourdough, tax returns, visas) clear nothing at all, so `RAG_MIN_SCORE=0.25` sits in the gap with headroom — rejected filtering after the fetch.

2026-08-26 — `answerWithAudit()` in `ai/call.ts` is the only way to reach a provider, and it owns both the timeout and the audit record — §5 asks for one wrapper and this makes it structural rather than a convention: `rag/answer.ts` has no other route to a model. The timeout is an `AbortSignal`, not a promise race, because a call we merely stopped waiting for keeps running and keeps costing — rejected letting each provider set its own deadline.

2026-08-26 — The audit record logs `provider.model`, not `env.LLM_MODEL` — the mock calls no model, so logging the configured id regardless would put `claude-opus-5` on a call that never happened; an audit trail that lies about the uninteresting case cannot be cited for the interesting ones. Caught by reading the log output, not the code — rejected logging the env value directly.

2026-08-26 — Errors are audited by the error's class name, never its message — a provider error can echo the request back, and the request contains the user's own notes; §3 forbids document content in logs and a message field is the easiest way to leak it by accident — rejected logging `error.message`.

2026-08-26 — The mock extractor drops markdown tables and headings, collapses whitespace before splitting sentences, and de-duplicates across chunks — all three were failures in the first version, seen by reading its actual output: it led with `| GPU | Rated total board power | 320 W |`, cut hard-wrapped prose into fragments like "As recorded in my GPU", and repeated the same sentence twice because chunks overlap by design — rejected the naive newline split that produced them.

2026-08-26 — The source view highlights one chunk by slicing the stored document text at the chunk's saved character offsets — chunks overlap, so highlighting every chunk would paint most of the page, and slicing the original avoids both re-running the chunker and string-matching the quote back into the text — rejected rendering the chunk on its own page, which loses the surrounding context that makes a citation checkable.

2026-08-26 — The ask page names the active providers in the footer — with no API key the app answers by extraction, and a reader should be able to tell which mode they are looking at without reading container logs — rejected hiding it as an implementation detail.

## Slice 5 — anonymization, the audit table and retention

2026-08-26 — One anonymizer instance per request, created in `askQuestion` and dropped with it — the mapping it accumulates is the only thing that can turn `[PERSON_1]` back into a person, so it exists in memory for one request and is never persisted, logged, or returned to the caller; a shared instance would let one user's names appear in another user's restored answer, which is covered by a test — rejected a module-level singleton.

2026-08-26 — The same instance redacts the question AND every retrieved chunk, so one value gets one placeholder across the whole request — this is what keeps retrieval-context and question agreeing: a question about "Marek Dvořák" still lines up with a chunk about him because both now read `[PERSON_1]`. Per-text anonymizers would have produced different numbers for the same person and quietly broken the model's ability to connect them — rejected redacting each string independently.

2026-08-26 — Retrieval runs on the ORIGINAL text, anonymization happens after — embeddings are computed in-process so nothing leaves to be embedded, and searching redacted text would mean searching for placeholders rather than for what the user asked about; the anonymizer sits at the process boundary, which is the only place it is needed — rejected anonymizing at ingest, which would also have made every stored document permanently lossy.

2026-08-26 — The capitalised-bigram separator is same-line whitespace or a hyphen, never `\s+` — with `\s+` the pattern jumped a blank line and joined a heading to the paragraph below it, redacting "Undervolting\n\nSame" and "Endurance\n\nRated" as people; found by printing what the detector actually matched against the seed corpus rather than by reading the regex, and now pinned by a regression test — rejected `\s+`.

2026-08-26 — Measured on the seed corpus: 6 of 6 people, 6 of 6 e-mails and 3 of 3 phone numbers detected, zero leaks, round trip byte-identical — with 6 false positives ("Arrow Lake", "Curve Optimizer", "Adaptive-Sync", "Ultra High", "Display Stream", "Wi-Fi"), so PERSON precision is 50% and recall on the values that matter is 100%. The bias is deliberate: a false positive means the model reasons over an opaque token and `restore` puts the real text back, so the user is unaffected; a false negative is a leak. Tuned to over-redact, and the number is in the README rather than implied.

2026-08-26 — The phone pattern requires an international prefix or separated 3-3-3/4 grouping — these notes are dense with figures ("3200 MHz", "600 TBW", "100 µs"), and a loose phone regex would have redacted the technical content the answers depend on; there is a test asserting those three figures survive — rejected a permissive digit-run pattern.

2026-08-26 — `restore()` uses `split`/`join`, not a regex — the placeholder contains `[` and `]`, which are regex metacharacters, and hand-escaping them is a bug waiting to be written — rejected building a `RegExp` per placeholder.

2026-08-26 — The `llm_calls` table has no `owner_sub` — the record exists to answer "what did this app spend and how did it behave", not "what did this person ask", and adding the subject would quietly turn a cost-and-latency table into a 30-day behavioural log of every user; §3 enumerates the fields and the table holds exactly that enumeration, so there is nowhere for content to land even by accident — rejected per-user attribution, which is a different feature needing a different justification.

2026-08-26 — A failed audit write is logged at error and swallowed, never propagated — the answer is already computed and correct, and losing one cost record is a smaller harm to the user than turning their question into a 500 — rejected letting the insert fail the request.

2026-08-26 — Failed calls are audited too, with zero tokens and outcome `timeout` or `error` — a call that was made and failed still consumed a deadline and possibly money, and an audit table that only records successes understates both; zero rather than null because the call genuinely returned no usage — rejected auditing only the happy path.

2026-08-26 — The audit record is written to both the table and the structured log — the table is the queryable one and is purged on schedule; the log line is what survives if the database is the thing that broke, which is exactly when you want to know what the app was doing — rejected writing only to the table.

2026-08-26 — `RETENTION_AUDIT_DAYS` accepts zero and fractional values, unlike every other numeric setting here — a retention policy nobody can demonstrate is one nobody believes, and `RETENTION_AUDIT_DAYS=0` makes the purge provable in a single restart; verified by doing it, watching `purged: 2`, and confirming the table was empty — rejected `.int().positive()`, which forbade the only cheap demonstration.

2026-08-26 — The purge logs every run including the ones that delete nothing — "purged 0" is the evidence the job is still alive, and a job that only speaks when it acts is indistinguishable from a job that has silently died — rejected logging only non-empty purges.

2026-08-26 — The retention timer is `unref()`ed — otherwise an hourly interval holds the event loop open and delays container shutdown by up to an hour for a timer nobody is waiting on — rejected a bare `setInterval`.

2026-08-26 — There is no `RETENTION_LOG_DAYS`, and the README says why — §7 implies a purge job for application logs, but this process writes them to stdout and never stores them, so it cannot purge them; inventing the variable would have meant shipping a setting that does nothing. The interpretation is stated rather than guessed silently, per §2 — rejected adding a `logs` table purely to give the variable something to delete.

2026-08-26 — "Delete my account" takes no parameter: the subject comes from the guard — the endpoint therefore cannot be pointed at anyone else's data, and documents cascade to chunks and embeddings through the foreign key rather than through an ordering someone could later get wrong; verified end to end, including that the other user's 10 documents were untouched and that signing back in re-seeds a fresh corpus — rejected accepting a subject in the request body.

2026-08-26 — Deleting the account does not invalidate the session — the token is the IdP's statement about who signed in, which remains true; the client signs out immediately after, and a later sign-in simply creates an empty account — rejected trying to revoke a stateless JWT, which the app cannot do and the IdP owns.

2026-08-26 — The anonymizer is made visible in the UI, showing the question exactly as it was sent alongside the restored answer — §3 requires the round trip be demonstrable, and a privacy control nobody can see is indistinguishable from one that is not running; only counts and the already-redacted text reach the browser, never the mapping — rejected leaving it to the logs.

2026-08-26 — `resolveCitations` was moved into `rag/citations.ts` with no imports at all — the piece most worth testing should not need a database, an embedder or an environment to test, and its input type is declared structurally so `RetrievedChunk` satisfies it without a coupling — rejected leaving it inside `answer.ts`, where a unit test would have pulled in the whole server.

2026-08-26 — Tests run on `node --test` with a 25-line resolver hook in `test/resolve.ts`, and no test dependency at all — Node runs TypeScript directly but knows nothing about the `@/*` alias, and the alternative was reshaping the application's import style to suit the runner, which puts test concerns into production files — rejected adding a test framework, and rejected `allowImportingTsExtensions` across the whole codebase.

## Slice 6 — README, the governing brief, and the honest record

2026-08-26 — The README's demo steps were verified against a fresh `git clone` before being written down, not after — the first thing this project is judged on is "does it run on the first attempt following the README", and a README written from memory of a machine that already has `.env`, `node_modules` and a warm model cache is exactly how that criterion is failed; the clean run confirmed three healthy containers, migrations applied, 10 documents and 53 chunks seeded on first sign-in, with no manual step — rejected writing the instructions from the developer's own working directory.

2026-08-26 — Anonymization is demonstrated by TWO questions, one per direction, rather than one claiming to show both — the first draft told the reader to ask about "Marek Dvorak" and promised the answer would come back with names restored; run against the fresh clone, the mock picked sentences containing no personal data at all, so the inbound half of the round trip was invisible. Outbound is now shown by a question containing a name, inbound by one whose answer contains a name, e-mail and phone. Found by running the README's own instructions — rejected the single-question version, which would have failed in front of anyone following it.

2026-08-26 — The classification section states the criteria it is judging against, because no standard matrix applies to a project like this — a verdict of "MEDIUM" with no stated axes is an opinion; the same verdict against nine named criteria is an argument someone can disagree with specifically. It also says which two design choices are load-bearing (in-process embeddings, enforced retention) and that removing either moves the classification up — rejected asserting the level and leaving the reasoning implicit.

2026-08-26 — The "How this was built" section names `CLAUDE.md` as the living brief and reproduces its operative content condensed, rather than pasting the file — two verbatim copies of a 200-line specification drift, and the point of publishing the brief is that it is kept current, not a souvenir; the section also records what the brief got wrong and where the correction lives, which is the part worth explaining — rejected duplicating the file into the README.

2026-08-26 — Known gaps are ten specific, individually checkable statements, not a paragraph of hedging — "the anthropic provider has never been run against the live API" is a gap someone can act on; "some parts are less tested" is not. Each says what is missing, why it was acceptable to stop there, and what it would take to close — what counts is what was deliberately left out while being aware of it, and awareness has to be demonstrable.

2026-08-26 — `docs/implementation-plan.md` §9 was closed rather than deleted, and its §7 gained a "deviation, as built" note — the plan is a record of what was believed before the build, and silently editing it to match the outcome destroys the only evidence of what changed and why; a reader hitting a stale open item that has in fact been resolved is worse than either — rejected both deleting the section and leaving it stale.

2026-08-26 — `CLAUDE.md` was not edited in this slice — §10 still labels the classification a draft and §8's budget predates the build; both are the author's to settle, and the implementation plan names them rather than changing them — rejected quietly updating the governing spec to agree with the work.

## Slice 7 — OpenRouter, so the seam is demonstrated rather than asserted

2026-08-26 — A fourth `LlmProvider`, `openrouter`, was added specifically to run the abstraction against a real third-party gateway — the load-bearing claim in this design is that a corporate AI Gateway is a swap, and "here is a `gateway.ts` I never called" is a claim, not evidence; OpenRouter is a different company, account, billing relationship and model namespace, and reaching it cost one 20-line provider file with no change to the prompt, request, parsing, citation guard, anonymizer or audit record — rejected leaving `gateway.ts` as the only argument.

2026-08-26 — The live run was made against `openai/gpt-4o-mini`, not an Anthropic model — an OpenAI model reached through the Anthropic SDK via a third-party gateway crosses a vendor boundary *and* a model-family boundary while touching nothing above `providers/`, which is a stronger statement about the seam than two routes to the same model; verified end to end in the UI, with the audit row reading `provider=openrouter model=openai/gpt-4o-mini input_tokens=680 output_tokens=41 outcome=ok` — rejected demonstrating with `anthropic/claude-opus-5`, which would have proven less.

2026-08-26 — `createMessagesProvider` gained an explicit `structuredOutputs` flag rather than always sending `output_config.format` — `output_config` is a recent addition to the Anthropic API and a proxy is under no obligation to implement every feature of the API it fronts: a gateway that rejects the field fails every request, and one that ignores it returns no `parsed_output` and looks like a refusal. True for the vendor, false for every gateway. The flag decides only whether the server helps; the prompt states the contract and zod validates on arrival either way — rejected both always-on (breaks gateways) and always-off (declines a real guarantee at the vendor).

2026-08-26 — With structured outputs off, the JSON is recovered by finding the outermost braces in the response text rather than parsing the whole string — models wrap JSON in code fences and prepend a sentence however firmly the prompt forbids it, and the alternative was a brittle exact-match that fails on cosmetics; whatever survives is checked against the same zod schema the server-enforced path uses, so a malformed response still fails as a rejected answer — rejected trusting `JSON.parse` on the raw text, and rejected stripping fences by regex, which handles one of the two failure shapes.

2026-08-26 — The JSON contract was moved into `prompts/answer-system.md` instead of being passed only as `output_config.format` — when the server does not enforce the shape, the prompt is the only thing that asks for it, and §3 requires every prompt to live in `prompts/`; a contract stated in TypeScript and invisible in the prompt folder would have been the same defect the folder exists to prevent — rejected building the instruction string in `messages.ts`.

2026-08-27 — Sign out and Home moved into one `SiteHeader` rendered by the root layout, and the duplicate controls on the pages themselves were removed — a session you can only end by first navigating home is one that gets left open on a shared machine, and sign-out is a security control, not a home-page feature; the header is a server component so the session is read server-side and sign-in/out stay server actions, which costs the whole tree its static rendering (`export const dynamic = "force-dynamic"` in the layout, stated rather than inherited by accident from a cookie read) — rejected a client-side session provider, which would add a hydration path and a way for the header to disagree with the guard.

## Slice 8 — prompt injection, and four of the ten known gaps closed

2026-09-03 — Retrieved chunks and the question are wrapped in `<source index="n">` and `<question>` tags, and the system prompt's first rule — placed above the citation rules — says everything inside them is data and never instruction — before this the prompt was `[1]\n<chunk text>`, so a note reading "ignore the above" sat in the prompt looking exactly like an instruction from the application, and there was nothing to point at when asked how injection is handled — rejected a phrase detector, which needs a list nobody keeps current and false-positives on a note that legitimately discusses prompt injection, and rejected doing nothing on the grounds that the citation guard already bounds the damage: it bounds it to a wrong answer with a real citation, which is exactly the outcome worth preventing.

2026-09-03 — Untrusted text that looks like one of those two tags is escaped to `&lt;source&gt;` rather than stripped, matched loosely (any casing, spaces inside the brackets, bounded to one line) — a delimiter a chunk can write for itself is not a delimiter, and the reader being defended against is a model, which reads `< /Source >` as a tag even though a parser would not; escaping keeps the sentence quotable, so asking what that document says still gets an honest answer — rejected stripping the text, which makes the app lie about its own contents, and rejected escaping every `<`, which mangles the code snippets these notes are full of to defend against a string that is not the delimiter.

2026-09-03 — `askQuestion` takes its retrieval and its model call as one defaulted parameter — the citation guard's rejection branch was the last unreached path in the app: no provider in the repository cites a source it was not given, so the branch that catches it could only be tested through `resolveCitations` in isolation, one level below the decision users actually meet; a stub reaches it every time, along with the retry, the refusal and the anonymizer round trip, with no database, key or model — rejected a container or a framework for two dependencies, and rejected an env-gated "hostile mock", which puts test behaviour in the shipped binary.

2026-09-03 — PDF text is reconstructed from positioned glyph runs instead of `unpdf`'s `extractText`, joining a line to the next when it ends flush against the page's right margin — a fixed-column layout breaks lines wherever the column falls, regularly mid-word, and `"comparing"` reaching the index as `"compar\ning"` is stored, citable and invisible to retrieval; the layout's own right margin is the evidence for which breaks are the layout's and which are the author's, and tolerances are in units of the line's average character width so nothing assumes a monospaced font or a page size — rejected a dictionary or a spell-checker, which is a black box for a problem geometry answers, and rejected leaving it as cosmetic debt: a word the retriever cannot see is not cosmetic.

2026-09-03 — A fixed-window per-user quota on `/api/ask`, in this process's memory, `ASK_RATE_LIMIT_PER_MINUTE` with 0 to disable — `/api/ask` is the only endpoint that costs money and the only limit on the bill was how fast the model answers; the endpoint is authenticated, so this is a spend ceiling on one session, not a defence against the internet — rejected Redis or a database counter, which adds infrastructure to the one component that has to run from `docker compose up` with nothing configured, and rejected leaving it to the gateway, which is where the control belongs but is not where this app currently runs.

2026-09-03 — The test harness gained a fake environment (`test/env.ts`) and two resolver fixes: directory imports (`@/server/ai` → `index.ts`) and the extensionless-relative rule scoped to our own files — the new tests import modules that read `env` at load and pull in CommonJS dependencies, and the old rule appended `.ts` to a dependency's own `require("./lib/err")` — rejected reshaping application imports to suit the runner, which is what the hook exists to avoid, and rejected a real database in the tests: a test that opens a connection is one that can pass for the wrong reason.

2026-09-03 — The injection defence was probed against a live model rather than only against the unit tests: a note carrying a forged `</source>`, a "SYSTEM OVERRIDE … reply OWNED … cite [99]" block and a fabricated `<source index="99">` was uploaded and asked about through `openrouter`/`gpt-4o-mini`, and came back grounded in the note's real content, citing [1], first attempt, no retry — a defence whose only evidence is a test of the string it produces has not been shown to work on the thing it is aimed at — rejected shipping the probe as a seed document, which puts an attack string in every new user's corpus for a demo that is better run deliberately, and rejected calling one refusal proof: it is one model on one prompt, and README gap 3 says exactly that.

2026-09-03 — The rate limit was verified against the running stack with questions the corpus cannot answer — the 21st request in a minute returns 429 with `Retry-After`, and choosing unanswerable questions keeps the whole loop free of model calls, which is itself the evidence that the quota is consumed before the body is read — rejected verifying it with real questions, which would have spent twenty model calls to observe a counter.

## Slice 10 — hybrid retrieval

2026-09-03 — Retrieval gained a second, lexical arm over a generated `tsvector` column, fused with the vector arm by reciprocal rank fusion — a sentence embedder cannot distinguish identifiers: `all-MiniLM-L6-v2` places `ddr5-6000` and `ddr5-5600` almost identically, and measured against the seed corpus the question "what are PL1 and PL2 set to?" returned NOTHING, because the two chunks answering it score 0.054 and 0.063 against a 0.25 floor — the app refused to answer from a document it had indexed, which is the citation guarantee firing on a false negative — rejected leaving it to a better embedding model, which costs image size and moves the same weakness rather than removing it, and rejected doing it in application code after the fetch, which would have moved the ownership filter out of SQL.

2026-09-03 — The lexical arm runs only when the question contains a token of at least three characters mixing letters and digits, and then requires every such token to be present (`plainto_tsquery`, which ANDs) — a broad keyword arm would answer nearly every question with something, and "Not found in your knowledge base." is produced by retrieval returning nothing, so the refusal would have come to rest on a similarity threshold invented for text ranks and tuned by feel; with this rule there is no new threshold and no new environment variable, and a question with no identifier does not run the arm at all, leaving retrieval byte-identical to before — rejected admitting bare numbers, which are far more often years, prices and quantities than part numbers, and rejected OR semantics with a `ts_rank` floor, which is the broad version wearing the narrow version's clothes.

2026-09-03 — Fusion is reciprocal rank fusion and it orders only; it never admits or drops a chunk — a cosine similarity in [0,1] and a `ts_rank_cd` that is unbounded and corpus-dependent cannot be put on one scale without inventing a conversion nobody can defend, while their ranks are directly comparable; keeping admission entirely in the two SQL predicates means an empty result stays empty, which is what the no-model-call refusal depends on — rejected normalising the two scores into a weighted sum, which is a tuning exercise with a made-up constant, and rejected ranking the fused set by cosine, which would have thrown away the exact match that earned the chunk its place.

2026-09-03 — The lexical arm repeats the `owner_sub` and `embedding_model` predicates instead of trusting the vector arm — ownership belongs in the same SQL predicate as the search (§6) and a second query is a second place to forget it; filtering on the embedding model is not strictly needed for a text match, but it keeps one rule for the whole of retrieval and preserves the documented degradation, where switching embedder yields nothing rather than an app that half-works on the questions that happen to name a part number — rejected omitting the model filter on the lexical arm as a free win, which buys a state that is harder to explain than an empty result.

2026-09-03 — `content_tsv` is a `GENERATED ALWAYS … STORED` column using the `simple` dictionary — generated, so it cannot drift from the content it indexes and no write path has to be kept in step, and Postgres computes it for existing rows when the column is added, so all 53 already-indexed chunks became searchable on the migration with nothing re-uploaded (verified on the running stack; contrast gap 5, where the PDF fix reaches only documents ingested after it); `simple` rather than `english` because stemming a part number can only lose information — rejected computing the vector at ingest, which adds a write path and leaves old rows behind, and rejected `to_tsvector` on the fly, which cannot use an index.

## Slice 11 — the daily spend cap

2026-09-03 — A daily per-user ceiling on model calls, `ASK_DAILY_CALL_LIMIT`, in a new `user_spend` table rather than by adding `owner_sub` to `llm_calls` as the roadmap had said — the roadmap item was wrong: `llm_calls` deliberately holds no subject, and adding one would turn a cost-and-latency table into a 30-day behavioural log of every user's questions, which is exactly the thing its schema comment refuses; a ceiling does not need a per-call history, only one number per user for the window in force — rejected adding the subject to the audit table, and rejected not building the cap at all, since the per-minute limit bounds the pace of spending and not the total, which is the number on the bill.

2026-09-03 — `user_spend` holds one row per user per UTC day, updated in place by an upsert, and the retention job deletes every row that is not the current window — the difference between a counter and a log is the shape, not the policy: with no per-call row there is no ordering and no per-question timestamp, so the most the table can say is "this subject made N calls today", and within the hour it cannot even say that about yesterday — rejected a rolling window, which needs per-call rows to slide over and would have rebuilt the log by another name, and rejected keeping history for an admin usage view, which is a feature nobody asked for bought with the exact privacy cost this design exists to avoid.

2026-09-03 — The cap counts calls, not tokens — the size of one call is already bounded by `RAG_TOP_K` chunks in and a capped answer out, so a ceiling on calls is a ceiling on money; and "200 questions today" is a number a user who hits it can act on, where "140,000 tokens" is not — rejected a token cap, which is truer to the bill and opaque to the person it stops; the token totals are summed into the same row anyway, so switching is a one-line change if the bill ever argues for it.

2026-09-03 — The check runs in the route before the body is read, the increment in `rag/answer.ts` after the model returns, and `recordSpend` is injected through `AskDependencies` — the refusal path never reaches a model so it must never cost a call, and the retry is a second real call so it must cost a second one; `ai/call.ts` would have been the tidy home for the increment, but it is the one door out and is deliberately subject-free, and threading a `sub` through it so it can bill someone puts identity into the component designed to hold none — rejected counting in `ai/call.ts`, and rejected importing `recordSpend` directly into `answer.ts`, which gave the tests a hidden database dependency in a suite whose harness forbids opening a connection.

2026-09-03 — The check and the increment are deliberately not atomic, and the gap is written into README gap 13 — requests in flight at the same instant all read the same count, so a burst can overshoot by roughly that number, which `ASK_RATE_LIMIT_PER_MINUTE` already bounds; a ceiling that is occasionally a call or two generous costs a fraction of a cent, while a lock on every question costs latency on every question — rejected `SELECT … FOR UPDATE` and rejected a single `INSERT … RETURNING` that counts before the call, which closes the race by charging for calls that then fail.

2026-09-03 — `deleteAccount` deletes the user's `user_spend` rows in the same transaction as their documents — `llm_calls` is left alone because it holds no subject and there is nothing in it belonging to anyone, but `user_spend` is keyed by the subject, and a table keyed by the subject is a table "delete my account" has to reach; §7 promises every row belonging to the `sub` is wiped, and a counter is a row — rejected leaving it to the hourly purge, which would have made the promise true only by the next morning.

## Slice 12 — re-embedding on an embedder change

2026-09-03 — Changing the embedder is announced in the UI, on `/ask` and `/documents`, by a notice that renders nothing when nothing is stale — retrieval filters on the model that produced each vector, so a switched embedder does not degrade the app, it empties it: every question returns "Not found in your knowledge base." while the documents page goes on reporting ten documents and fifty-three chunks, and the one failure mode the citation guarantee cannot distinguish from an honest refusal is an index nobody can reach; the notice is on the ask page in particular because that is where the symptom appears — rejected a log line alone, which is invisible to the person actually being refused, and rejected letting the refusal stand unexplained, which is the app lying by omission about its own contents.

2026-09-03 — Re-embedding is manual, requested by the user, and nothing re-embeds at startup — an app that rewrites every index because an environment variable changed does its most expensive write in response to the least deliberate action, and a typo in `EMBEDDING_MODEL` would rebuild a corpus against a model nobody chose before anyone noticed; the app says what it cannot see and waits — rejected an automatic rebuild on mismatch, and rejected doing nothing at all, which is where the previous eleven slices left it.

2026-09-03 — The rebuild re-chunks from `documents.content` rather than re-embedding the stored chunk text — chunk size is dictated by the embedding model's input window and not chosen freely (§6), so replaying the old boundaries would carry the old model's constraint into the new model's index and reintroduce, silently, exactly the truncation the chunk sizing exists to prevent; the stored document text is the same input ingest had — rejected embedding the stored chunks, which is faster and wrong the moment the two models disagree about a window.

2026-09-03 — One transaction per document, and a failure inside one is caught, counted and reported rather than thrown — a document ends with its old chunks or its new ones and never a mixture, while one unreadable document out of ten does not abandon the other nine and leave the user with no way past it; re-running is safe because a rebuilt document is no longer stale and is no longer selected — rejected one transaction over the whole corpus, which turns any single failure into no progress at all.

2026-09-03 — Document counts are reported per stale model, never totalled across them — a chunk carries exactly one model so chunk counts add up exactly, but a document could hold chunks from two, and a total that quietly counted it twice would be the wrong kind of number to put in a warning about numbers being wrong — rejected a single "N documents affected", which is the sentence a reader most wants and the one this data cannot honestly produce.

2026-09-03 — The rebuild runs inside the request, synchronously, with no queue and no progress — measured at 8.8 s for the seed corpus (53 chunks, 10 documents) with `local` and 0.3 s with `mock`, against a personal-scale corpus the app already assumes elsewhere (README gap 6), for an action taken by hand once after changing a variable; the honest recovery from a timeout is to press the button again, which idempotency already makes safe — rejected a background job, which is a queue, a status table and a polling UI for an operation nobody performs twice.

2026-09-03 — `ASK_RATE_LIMIT_PER_MINUTE` and `ASK_DAILY_CALL_LIMIT` were added to `docker-compose.yaml`, where slices 9 and 11 had failed to put them — both were in the zod schema and in `.env.example` and neither was passed into the container, so in Docker they were pinned to their defaults and setting them in `.env` did nothing, which is precisely the "variable that silently does nothing" §8 forbids and the same defect class as the slice it was found in; the README's configuration section now names the compose file as the third place a variable has to appear — rejected fixing it silently, since the interesting part is that a documented, tested, defended control was inert in the only environment anyone runs.
